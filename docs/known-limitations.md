# 已知限制

仓库提供可审查的源码、合成测试和部署模板。以下边界需要在每次实际部署中确认，不能由一次单元测试或一次成功请求替代。

## 千问工具、会话与语音

- 设计按 HTTP 工具 **3 秒总预算**准备缓存读取；真实平台曾出现约 **1 秒连接超时**。连接建立、TLS、代理和路由可能先耗尽预算，服务端处理快并不保证平台能连上。
- 同一个千问会话可能沿用之前的工具结果。Skill 要求每次重新取稿，但不能把提示词当成平台一定重取的证明。更新后应在新会话中核对真实工具调用、返回日期和内容。
- 网页 TTS 控件曾显示 500 字符输入约束。这只能说明该网页控件的行为，**不能推论平台原生 Speak 或眼镜整期朗读也只有 500 字符**。
- 本仓库约定最多 32 段、每段正文 600 字符，理论正文容量为 19,200 字符，外加日期和段号。它是数据结构容量，不是原生 Speak 的已验证上限，也不保证任意长度都能一次播完。
- 模拟器出现 Speak 调用、真机测试安装、真机开始发声、真机完整播完是不同证据。公开模板不包含可证明所有账号、型号、固件和长稿都通过的设备矩阵。
- 千问平台的插件标识、技能权限、测试安装和发布资格需由部署者在自己的账号完成。仓库中的 YOUR_PLUGIN_ID 必须替换。

## 数据与容量

- JSON 状态保存在单文件并整体加载进内存，只支持 **一个 API 进程、一个 Uvicorn worker**。不支持多副本横向扩容、多人账号隔离或高可用集群。
- 无自动历史清理、数据库迁移、来源重命名迁移或恢复管理界面。备份、保留周期和迁移由部署者管理。
- 原文超出整期容量时明确失败，不静默截断。多个详细来源会共享 32 段容量；输入上限不代表所有输入都能完整装入输出。
- 读取每一段时响应仍携带整期全文与完整来源，长稿分页会重复传输数据。网络慢时应测量实际响应字节和耗时，不通过提高验收门槛掩盖失败。
- 日期逻辑固定为 UTC+8，采集器查询最近七天。跨时区、补历史邮件或延迟超过窗口的场景需要显式操作。
- 来源 kind 只描述来源契约；仓库不会创建原始报告任务、邮箱订阅或上游监控。

## 生成与运行

- 原文正文不经过模型改写；整理和播客模式依赖所选 Codex 或 Pi 云模型的生成质量。结构、引用和容量检查不能证明每句话都忠实，内容仍需人工抽查。
- worker 使用已配置的 Codex 或 Pi CLI；当前 Pi 集成固定于 1.4.0。CLI 变化、认证、账号额度或服务可用性会影响生成，不能承诺任意版本和供应商都兼容；缓存读取仍独立运行。
- worker 的模型子进程关闭工具和 hooks，并移除 BRIEFING_* 环境变量。这不表示仓库自带了宿主 Codex 的原生 PreToolUse、Stop 或 SubagentStop 强制保障。是否支持、受信任并真正触发须在宿主环境另行核实。
- Gmail 采集器使用 Apps Script 的调度与配额。十五分钟触发器不是精确到秒的交付承诺；运行失败须看状态与回执。
- 设置页会话保存在内存，API 重启会退出登录。当前管理凭据是单一角色口令，未提供多管理员、账号找回或细粒度审计体系。
- Linux systemd、Nginx 与证书文件都是部署模板，需按本机路径和域名调整；这不是一键托管服务。

## 首次配置与容器

- 安装 Skill 与任务调度是不同能力。OpenCode/Codex 可以执行配置流程，但任务列表与邮件交付来自用户实际使用的宿主；不存在的能力必须补齐真实入口，不能靠导出文件替代。
- 首次流程只选已有、启用、每日、非监控任务；日程不能证明任务目的。Codex 自动发现的 monitoring 为 null，必须查看原任务后补充核对。
- CLI 的 digest 检查绑定方案内容，--confirm 记录操作者决定，不能独立证明用户真的批准。配置助手须先展示方案并取得回复；没有答复不会自动继续。
- 私有策略和初始偏好只支持新实例初始化。没有自动升级已有来源集合、清空历史或合并生产状态的能力。
- 当前 Docker 模板内置 Pi；Codex 采用已有 Linux CLI 环境，不是更改 Compose 中一个名称就能自动装好。容器内 HTTP 仅允许专用 API 主机与回环地址，对外仍需有效 HTTPS。
- Docker/Pi 可以先空配置启动，再在已认证的 HTTPS 设置页选择服务和模型、输入 API key。未配置时 worker 等待，不领取任务；这只证明服务能够等待配置，不能计作生成链路通过。Codex 的认证与中转配置不由此页面管理。
- 网页内置模型目录是 Pi 1.4.0 的随包快照，不实时查询模型上线、下线、价格、账号权限或余额。单凭据表单未覆盖 OAuth、AWS 区域、Azure 部署及 Cloudflare 账号等额外配置路径；自定义模式仅支持页面列出的 OpenAI Chat Completions 兼容协议，不能据此承诺任意“OpenAI-compatible”服务都可用。
- 保存模型设置不会调用模型做连接测试，也不会证明 key 有效、服务有额度、模型可用或输出忠实。配置供下一次生成使用，已有缓存和正在执行的任务不会因此立即重做；实际生成结果须另行验证。
- 网页不回显已存模型密钥，也不放入浏览器持久存储；服务仍需在受限持久目录保存可供 worker 使用的密钥。该目录与备份都属于秘密材料，不是公开诊断附件。切换服务或接口时需重新输入 key，不能将旧 key 自动发送到新目标。
- 容器和模型替身测试只能证明相应合成路径，不能证明真实云端模型质量、账号权限或眼镜播放。Pi 的 API key 与千问 HTTP 工具 read token 相互独立。
- 播客模式提供双人对话文字。双声线音频、设备表现以及平台具体权限需实测；没有明确错误证据时不判断为权限拒绝。
- 自定义双声线音频生成、音频文件播放器和服务端主动推送到眼镜均未实现。当前路线是用户语音触发 HTTP 缓存读取，再由平台原生 Speak 朗读；未来设想不能写成已有功能或可用权限。

具体通过条件和记录方式见 [验收文档](acceptance.md)。
