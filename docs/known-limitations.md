# 已知限制

仓库提供可审查的源码、合成测试和部署模板。以下边界需要在每次实际部署中确认，不能由一次单元测试或一次成功请求替代。

## 千问工具、会话与语音

- 设计按 HTTP 工具 **3 秒总预算**准备缓存读取；真实平台曾出现约 **1 秒连接超时**。连接建立、TLS、代理和路由可能先耗尽预算，服务端处理快并不保证平台能连上。
- 同一个千问会话可能沿用之前的工具结果。Skill 要求每次重新取稿，但不能把提示词当成平台一定重取的证明。更新后应在新会话中核对真实工具调用、返回日期和内容。
- 网页 TTS 控件曾显示 500 字符输入约束。这只能说明该网页控件的行为，**不能推论平台原生 Speak 或眼镜整期朗读也只有 500 字符**。
- 本仓库约定最多 32 段、每段正文 600 字符，理论正文容量为 19,200 字符，外加日期和段号。它是数据结构容量，不是原生 Speak 的已验证上限，也不保证任意长度都能一次播完。
- 模拟器出现 Speak 调用、真机测试安装、真机开始发声、真机完整播完是不同证据。公开模板不包含可证明所有账号、型号、固件和长稿都通过的设备矩阵。
- 千问平台的插件标识、技能权限、测试安装和发布资格需由部署者在自己的账号完成。仓库中的 YOUR_PLUGIN_ID 必须替换。

## 数据与容量

- JSON 状态保存在单文件并整体加载进内存，只支持 **一个 API 进程、一个 Uvicorn worker**。不支持多副本横向扩容、多人账号隔离或高可用集群。
- 无自动历史清理、数据库迁移、来源重命名迁移或恢复管理界面。备份、保留周期和迁移由部署者管理。
- 原文超出整期容量时明确失败，不静默截断。多个详细来源会共享 32 段容量；输入上限不代表所有输入都能完整装入输出。
- 读取每一段时响应仍携带整期全文与完整来源，长稿分页会重复传输数据。网络慢时应测量实际响应字节和耗时，不通过提高验收门槛掩盖失败。
- 日期逻辑固定为 UTC+8，采集器查询最近七天。跨时区、补历史邮件或延迟超过窗口的场景需要显式操作。
- 来源 kind 只描述来源契约；仓库不会创建原始报告任务、邮箱订阅或上游监控。

## 生成与运行

- 原文正文不经过模型改写；整理和播客模式依赖 Codex 的生成质量。结构、引用和容量检查不能证明每句话都忠实，内容仍需人工抽查。
- worker 依赖已认证并兼容所用参数的 Codex CLI。CLI 变化、账号额度或服务可用性会影响生成；缓存读取仍独立运行。
- worker 的模型子进程关闭工具和 hooks，并移除 BRIEFING_* 环境变量。这不表示仓库自带了宿主 Codex 的原生 PreToolUse、Stop 或 SubagentStop 强制保障。是否支持、受信任并真正触发须在宿主环境另行核实。
- Gmail 采集器使用 Apps Script 的调度与配额。十五分钟触发器不是精确到秒的交付承诺；运行失败须看状态与回执。
- 设置页会话保存在内存，API 重启会退出登录。当前管理凭据是单一角色口令，未提供多管理员、账号找回或细粒度审计体系。
- Linux systemd、Nginx 与证书文件都是部署模板，需按本机路径和域名调整；这不是一键托管服务。

具体通过条件和记录方式见 [验收文档](acceptance.md)。
