# 安装千问早报

本 Skill 为 Codex、OpenCode 等 Agent Skills 宿主提供同一接入流程。它是配置助手；眼镜侧朗读指令是项目的 qwen-skill/SKILL.md，两者不要混装。

项目仓库：[reknottycat/qwen-briefing-starter](https://github.com/reknottycat/qwen-briefing-starter)。

先定位用户现用或准备安装的 qwen-briefing-starter 仓库，阅读项目的 AGENTS.md、docs/setup.md 和适用的 docs/operations.md。仅安装了 Skill 而没有项目时，在用户当前工作目录或已指定目录取得官方仓库，再读取该版本说明。已有生产实例时先区分新建与维护，不能把首次初始化输出覆盖已有状态。

顺序固定为：**发现现有任务 → 用户确认来源方案 → 用户确认服务器方案 → 部署与验证 → 用户登录千问平台并接入设备**。两次确认须来自用户对同一份具体方案的明确回复，或会话中已有的同等授权。确认文件只是记录，不证明人类已确认；没有回复时不能自行填写确认标记。只暂停依赖确认的步骤，继续有用的只读准备。

## 一、发现现有任务，提出来源方案

优先用当前宿主已有的任务连接器或 API。Codex 本地自动化可由项目 onboarding 命令读取指定 automations 目录；其他宿主把实际查询结果整理成标准任务 JSON。确切命令和字段见 docs/setup.md 与 python -m briefing.onboarding --help。

只读任务 ID、名称、启用状态、实际日程与时区、目的和完整提示词。首次接入只考虑**已经存在、启用、每天运行、已核实不是监控的报告任务**：

- 排除定期查状态、等变化、发现回复才通知等监控，即使它们每天运行。
- 排除周报、一次性、暂停或日程/用途未核实的任务。不能只凭名称或缺少监控关键词判定。
- 不新建、克隆或迁移任务，不把监控改写成日报，不把示例来源当成用户任务。
- OpenCode 能读 SKILL.md，不代表它有任务调度、任务列表或发信能力。缺少入口时请用户指向真实任务宿主或导出，不伪造调度器。

保留原任务 ID、名称、日程、时区和报告要求。给出可审阅表格：建议选入项、新闻/学习/工作分类、原文/整理模式、simple/standard/detailed 详略及选择理由。当前初始导出 note 固定为空，短偏好在服务启动后通过管理 API 设置，不承诺已经写进初始配置。CLI 不提供来源别名字段；名称不符合邮件契约时说明具体限制，不能私自重命名原任务或伪装已经支持别名迁移。

工作开关默认关闭；选择工作分类不自动授权打开。播客仅在用户明确要求时作为备用文字模式提出，不承诺双声线音频。

**展示完整表格并等待用户确认或修订。此时不开始部署、不连接千问控制台，也不提前要求服务器配置。** 用户确认后以相应 digest 记录任务确认；修改了选择或偏好须以新方案为准，不能用旧确认覆盖新内容。

## 二、再确认服务器方案

任务方案确认后，说明四个模块：原任务宿主、Gmail 云采集、服务器 API/worker、千问 HTTP 工具与 Speak。云模型调用发生在服务器 worker；眼镜只读取缓存。整理模式下，报告正文和偏好会发送到所选模型服务。

服务器生成方式只提供 **Codex 或 Pi**。已有 Codex 的用户可复用其认证与中转服务配置；Pi 是通用轻量选项。两者调用云端模型，本项目不需要 DGX 或 GPU。OpenCode 是配置 Skill 的可选前端宿主，不是本仓库的服务器生成后端；不要再添加其他 Agent 框架或自建模型 API 适配器。

只询问必要的非秘密信息：SSH 别名或目标主机说明、Linux/Docker 可用情况、部署目录、HTTPS 域名、Codex/Pi 选择。Pi/Docker 允许先确认服务器，在部署后的 HTTPS 设置页再选提供方、模型和接口；server.json 可同时省略 provider、model、llm_base_url，不能留下部分配置。Pi/Linux 手动模式仍需 provider/model，必要时确认自定义基础地址。SSH 密钥、密码、Cookie、模型 API key 和角色 token 由用户在自己的受限文件或平台私有配置中填写，不进入聊天或方案 JSON。

形成第二份具体方案，列出目标主机、目录、域名、复用/新建组件、生成方式、凭据文件位置及原任务拟追加的邮件交付要求。**等待用户明确确认服务器方案，再记录绑定当前任务方案的服务器 digest。** digest 只覆盖 docs/setup.md 列明的 server.json 字段；目录、凭据路径和额外交付约定另存在受保护的部署记录，恢复时两者一起核对，不能说这些内容已被 digest 绑定。目标或生成服务实质改变后重新确认受影响部分；同一授权不重复询问。

## 三、导出配置、部署、核对

两份方案确认后，用项目 onboarding export 导出来源策略、初始偏好、摘要和邮件交付要求，保存到忽略的 runtime/。不要硬改仓库的十个示例名称代替用户选择。

执行 docs/setup.md 和当前 deploy/docker/README.md 中对应方案。API 与 worker 使用同一份 BRIEFING_SOURCE_POLICY_PATH；BRIEFING_INITIAL_PREFERENCES_PATH 只初始化新状态，不能迁移或覆盖现有状态。已有数据需按维护流程备份、在副本中验证，不能清空数据以绕过初始化错误。

四个角色凭据独立分发。Docker/Pi 的模型 key 由用户在已登录的 HTTPS 设置页输入，经管理 API 保存到私有持久目录，worker 只读；Linux/Pi 手动模式使用本机 key 文件。容器内 HTTP 只用于显式允许的专用服务地址，对外仍用 HTTPS。检查配置时报告文件位置与检查结果，不回显秘密。

Docker 可在没有模型 key 时启动；未配置的 worker 等待，不领取任务。服务和 HTTPS 可用后，引导用户用本实例 manage.token 登录 /briefing/v1/manage/，在“整理早报，用哪个模型”选择内置服务与模型，或自定义 HTTPS OpenAI Chat Completions 兼容接口，再填写 API key。目录来自随包 Pi 版本快照，不代表账号权限、价格或当前可用性；OAuth 或需要额外凭据的内置路径不作通用兼容承诺。

网页只回读非敏感配置和已配置状态，不返回 key，也不把 key 写进浏览器持久存储或日志。相同模式、提供方、基础地址和协议可留空沿用密钥，只改模型也可沿用；改变目标必须输入新 key。遇到模型 revision 冲突，回读最新配置并复核，不能强制覆盖。不得索要用户把密钥发到聊天，或读出密钥作为验证证据。

保存后的配置用于下一次生成，无需重启；当前任务保持原配置。保存不执行供应商连接测试，也不证明 key 有效、额度可用、已有缓存重建或生成质量通过。先核对保存状态，再观察下一次授权生成的实际结果。Codex 认证与中转继续由现有 CLI 管理，不通过这个表单修改。

原任务宿主确实具备并获授权的邮件能力时，只追加已确认的交付规则，保留其日程、目的、启用状态和完整正文要求。export 只写本地配置，不能据此声称原任务已修改或邮件已发出。没有发信能力时如实列出缺口，不换一个调度器伪装完成。

先用隔离合成数据验证服务、来源策略、权限、生成与缓存，再接入真实报告。不要将合成邮件投进正式早报。分别记录“配置完成、待真实触发、已收件、已发布缓存”。

## 四、最后连接千问平台与设备

前两项确认完成，且后端 HTTPS 与缓存读取可用后，才开始千问账号操作。请用户登录自己的千问 AI 硬件开放平台，优先复用已登录浏览器或合适连接器，核对实际账号与设备；不索取登录秘密。

本项目走云云 HTTP 工具加原生 Speak，不要求 APP SDK、MCP Server 或一个未经核实的“Gateway Key”。按 docs/setup.md 的官方流程创建 OpenAPI 插件、工具，调试后绑定设备和开发者模式。使用平台为当前用户生成的 pluginCode 与工具 code 替换 YOUR_PLUGIN_ID，不复用作者标识。read.token 只填到插件私有鉴权配置。

工具定义是字段参考，不宣称通用一键导入。当前页面或权限与文档不符时，报告实际错误或缺项；没有错误证据就不能说“平台不给权限”。账号迁移等身份决定由用户完成。

核对真实工具参数、返回内容、Speak 输入和设备播放。保留 3 秒 HTTP 预算。默认整期使用 full_spoken_text，明确段号才用 spoken_text；更新后在新会话观察实际取稿，不能仅凭提示词认定已调用。双人文案、双声线合成和设备播放分别核验。

默认只接入用户自己的私人 Skill 与设备。插件发布、Skill 提交、审核通过、测试安装、开始发声、整期播完分别记录；公开共享属于另一个发布范围。保留连接超时、会话旧结果和原生长稿播放的未验证边界。

## 恢复与维护

交付实例位置、所选来源与偏好版本、生成方式及各阶段真实状态。完整记录放受保护的 runtime/，公开文档只写通用流程。恢复时用 onboarding status 判断阶段，沿用有效确认，不自动推进未确认步骤。

日常修改来源、分类、模式、详略、备注或工作开关，转用 add-to-briefing，不要求用户重走安装流程。Docker/Pi 更换模型或轮换 key 直接使用既有模型设置页和 docs/operations.md；模型设置与朗读偏好分开保存，不能用偏好 PUT 更改模型。
