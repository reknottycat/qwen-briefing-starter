# 加入早报

前提：已有部署的 qwen-briefing-starter 后端、本地项目及单独配置的管理凭据。安装本 Skill 不会部署后端；修改上游 ChatGPT 任务还需要已授权的任务连接。

维护现有链路：**ChatGPT 线上任务生成完整报告 → Gmail → 云端收件/API → DGX 按模式备稿 → 千问 Speak 合成并播报**。默认整理后朗读，也支持原文朗读；播客是备用模式，不默认开启。这项技能不在 DGX 生成音频，不把线上任务迁到本机，也不承诺两种声线或 MP3。

## 先定位事实

先定位用户已经部署的 qwen-briefing-starter 项目。先读该项目的 `AGENTS.md`，再按任务读取下面的维护源；不要因当前工作目录不同而另建早报系统。路径已迁移时，找到用户现用项目后再改。

| 要查的事实 | 唯一维护源或现有入口 |
|---|---|
| 入选来源、准确名称、类型、事件标记、顺序与声明的详略初值 | `briefing/source_policy.json`；数组顺序即播放顺序，云端实际初值由 `preferences.default_preferences()` 构造 |
| 实际生效的分类、模式、详略、短偏好、工作开关及版本 | 云端 `state.preferences`；通过 `GET /briefing/v1/manage/preferences` 读取，不以本地 JSON 默认值代替 |
| 当日实际生成阶段与偏好版本 | `GET /briefing/v1/manage/status`；保存成功不等于新稿已经发布 |
| 管理契约与口播实现 | `briefing/preferences.py`、`briefing/api.py`、`briefing/store.py`、`briefing/worker.py`、`briefing/models.py` |
| 邮件交付格式 | `docs/mail-format.md`、`cloud-gmail/Code.gs` |
| 现行部署、重建、凭据位置 | `docs/operations.md` |
| 已部署版本、实际运行证据及未验证项 | 部署者保存在 `runtime/` 的私有运行记录、`docs/acceptance.md` |
| 相关历史错误 | `docs/lessons-learned.md` 中来源选择、投递与播报相关条目 |

上述文件路径均相对于项目根目录，API 路径基于现行 HTTPS 服务地址。文档中的旧数量、默认值或历史验收不能覆盖实际运行状态。不要在技能内另存来源清单、任务 ID、日程或有效偏好。

## 把请求落实到登记

- **查看登记**：读取管理 API，按其 `order` 列出准确名称、类型、有效分类、模式、详略和短偏好，同时说明 `work_enabled` 及当日生成阶段。纯查询不改配置、不触发发送或重建。接口暂不可达时，本地默认值必须明确标注，不能冒称有效设置。
- **加入来源**：从用户已指定或已选中的 ChatGPT 线上任务定位原任务，核对名称、说明、触发条件、日程和启用状态，确认没有重复项。只有目标任务确实无法确定时才询问。复用原任务，不新建副本；若不存在对应任务，说明缺口，不用 Codex automation 或 Windows 调度冒充。新增来源及其初始详略写入策略，未指定时用 `standard`；按运行参考同步来源并协调有效 preferences。已有来源不重复添加，其详略或备注按下一条办理。
- **修改分类、模式、详略、短偏好或工作开关**：先 GET 当前有效设置，再用独立 manage 凭据 PUT 管理 API。只更新获授权的 `category`、`mode`、`narration_detail`、`note` 或顶层 `work_enabled`，保留其他有效值；不改 JSON 默认值、不重启三组件、不重写上游报告。完整提交、并发和今日更新规则见运行参考。
- **调整顺序**：只移动目标来源的数组位置，保留其他来源的相对顺序和字段；不靠改名称或添加另一份排序表实现。
- **移除来源**：撤下该来源登记及这项早报集成的邮件交付附加规则，保留原 ChatGPT 任务本身和原始 Gmail。处理受影响的活动缓存，避免旧稿仍播出已移除来源；具体边界和步骤见下文运行参考。若用户明确只暂停今后收录，保留其指定的历史范围。

已授权的常规登记、同步和验证直接完成，不为同一操作重复确认。涉及新的含糊任务、范围冲突或平台权限阻断时，仅暂停依赖该信息的动作，继续完成其他准备。

管理上游时优先使用能操作 **ChatGPT 线上任务** 的现有连接器；没有相应能力时，使用已登录账号的任务页面。Codex automation 不是同一个任务系统。只有登记、实际偏好版本、交付附加规则和本次需更新的缓存均符合请求，才只回读核对。偏好保存后先查状态，不重复保存、另排重建、重启服务或发信来催进度。

## 模式、详略和偏好只约束备稿

每个来源独立选择 `mode`：`raw` 为原文朗读，不调用模型整理；`processed` 为默认的整理后朗读；`podcast` 是用户明确要求时才使用的双人对话备用 API 模式，主网页不展示。快照格式为 `mixed`，不能把整期强制改成播客。

`category` 是云端可管理的 `news` / `learning` / `work` 分类，初始映射读取 `briefing/preferences.py`，不在技能复制分类名单。新增后按用户已确认的用途核对有效分类；业务或生活资讯不自动等于工作日程，不能因“工作相关”就归入 work。千问消费三个入口：

- `daily`：新闻、独立的简单学习概要，以及开关启用后的可选工作。学习概要每来源最多 250 字符，不替代学习主稿。
- `learning`：学习主稿遵循用户保存的档位，初始学习来源默认详细，之后仍可调整；原文模式读取完整原文。
- `work`：工作日程，仅在 `work_enabled=true` 后启用，初始为 false。关闭后立即禁取工作入口，其他视图也排除工作；这不暂停原任务或邮件采集。

学习来源选 `raw` 时，原文绝不交给模型；daily 只用确定性的材料名称和“今天应该学什么”收听提示，learning 读原文。新闻来源选 `raw` 时，daily 直接照读原文。入口参数及实际缓存以当前 Qwen skill、worker 和读取 API 为准，不把分类保存成功当作各入口内容均已生成。

详略与 `note` 仅在 `processed` / `podcast` 生效。`raw` 下保存这些字段不会压缩原文，也不自动切换模式；切换到整理后朗读须有用户相应意图。原文模式的具体文本处理及分段以当前 worker 为准，不能为适配详略上限而悄悄截断原文。

| 用户说法 | `narration_detail` | 文字转口播目标 |
|---|---|---|
| 简单、简略 | `simple` | 每来源仅 1 段、最多 250 字符，无最低字数；保留结论、必要行动和关键条件 |
| 一般、标准 | `standard` | 核心信息及足以理解的背景、原因和主要行动 |
| 详细 | `detailed` | 保留原稿主要内容、解释、例子、步骤与练习，改成适合听的表达；不凭空扩写 |

整理/播客模式的一般和详细参考篇幅不硬凑，simple 才执行 1 段、250 字符硬上限；raw 主稿不套用详略限制。教学和语言练习在详细模式下保留关键教学、例题、练习及俄语原句，原稿没有的答案不补造。健康简单稿删重复病史和非必要份量，但若保留具体用量，须保留原稿的示例性质与适用条件。完整报告始终完整交付给 Gmail 和 DGX，不因对话或详略改成摘要、通知或只有链接的邮件。

备用 `podcast` 中，主持人用具体问题或自然过渡推动内容，讲解人展开原文已有的机制、例子、条件与练习。每个来源整体含两位角色，不机械轮流读段落、不捧场凑字，也不让主持人抢答听众练习。角色标签和换行计入字符上限；双人文案不是两声线验收。

`note` 最多 200 字符，只表达语气、信息重点或解释方式，例如“先讲结论，再解释原因”。它不能覆盖事实、日期、来源、俄文原句、练习不代答或篇幅规则，不能要求执行工具、修改上游任务或提取秘密，也不作为正文照读。只保存用户实际要求的偏好，不替用户添加事实判断；清除备注时写空字符串。

## 保留上游任务意图

只有用户授权的时间调整和邮件交付规则才修改现有 ChatGPT 任务。加入早报所需的交付附加规则可在本次接入授权内更新；改详略、短偏好、顺序或对话形式本身不授权重写报告任务或改日程。保存上游任务后重新打开核对，避免意外改变研究要求、触发条件、时间和启用状态。

`daily`、`weekly` 使用 `定时结果`，报告完成后发送；`conditional` 必须沿用该任务的 `新回复` 或 `新信息` 条件，仅出现符合条件的新内容时发送。无更新、运行中、失败或只有检查过程时保持静默。周报的具体日程以当前用户选择及原任务的实际日程为准。

收件账号、准确主题、首行事件标记及日期规则从项目邮件格式读取；第二行用 `简报分类：新闻`、`简报分类：学习` 或 `简报分类：工作` 标注交付分类。网页重归类后以云端有效 preferences 为准，旧邮件标签不能覆盖用户选择。发信前核对已连接身份，保留完整结果和来源链接，同一运行不重复发信。配置保存、发信回执、Gmail 收件、API 入库、DGX 发布和眼镜完整发声分别报告，不互相替代。

## 修改后落实到运行

执行变更时读取 [运行同步与验收](references/operations.md)，按“管理偏好”或“改变来源结构”选择流程。用户也可使用现行 HTTPS 地址下的 `/briefing/v1/manage/` 网页选择原文/整理后朗读、详略和短偏好；它与 Codex 使用同一云端有效设置，不是另一份登记。

完成时说明实际变更、保存的偏好版本、当日生成阶段及仍待触发或真机确认的部分。`no_sources` 表示偏好已保存但今日无原文，不能报告已有新稿；排队或生成中也不等于已发布。凭据、私密邮件、生成正文、偏好备注及完整回执保存在受保护且被忽略的 `runtime/`，不进入技能、Git或公开日志。
